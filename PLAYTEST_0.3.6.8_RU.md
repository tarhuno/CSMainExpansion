# 0.3.6.8-dev — падение ShopCatalog.snapshot в LAN-мире

## Причина

В присланном логе сервер упал с ArrayIndexOutOfBoundsException в LinkedHashMap.valuesToArray → ShopCatalog.snapshot → ShopBalance.onTick. Это возможно при одновременном копировании и изменении общего каталога клиентским и серверным потоками интегрированного сервера. Предыдущий перехват ConcurrentModificationException не покрывал этот вариант гонки.

## Исправление

Общий Mixin ShopCatalog подключает postApply-плагин Expansion: все исходные статические методы каталога получают JVM-флаг synchronized и используют монитор ShopCatalog.class. Тела методов, порядок товаров и правила нормализации не заменяются. Инициализатор класса не меняется. Перехват ошибок вместо синхронизации не используется.

ShopBalance использует этот же монитор для всей операции snapshot → подготовка изменений → replaceAll → сохранение. Клиентская синхронизация и другие операции каталога не могут вклиниться внутрь этого обновления. Исходный CSmain JAR на диске не изменяется и не включается в Expansion.

Ассортимент, цены, ограничения сторон и скины 0.3.6.7 сохранены. JSON магазина не удаляется и не сбрасывается; резервная копия обновления ассортимента остаётся before_expansion_0.3.6.7.json.

## Выполненная проверка

- Java 17 clean build с reobfJar прошёл.
- CatalogSynchronizationTest проверил покрытие всех статических API реального ShopCatalog без изменения инструкций и без загрузки игрового мира.
- Тест применил производственный преобразователь к модели каталога с LinkedHashMap и выполнил 40 000 конкурентных операций чтения/замены: не было исключений и частично заменённых снимков. Проверены независимость старого снимка и освобождение монитора после исключения.
- Шесть существующих автономных тестов прошли.

Эти проверки не запускают Forge/Minecraft; применение Mixin в реальной сборке и LAN-сценарий ещё НЕ проверены.

## Плейтест

1. Остановить игру, установить 0.3.6.8-dev на хост и второй клиент, оставив одну версию Expansion. Не удалять config/killfeedtacz_state.json.
2. Открыть тот же мир по LAN, подключить второго игрока. Одновременно открывать магазин на обоих клиентах, выбирать товары и покупать; выполнить `/csx skins` и `/csx skin`, несколько раз переподключить второго игрока. Дать серверу поработать хотя бы 5 минут, чтобы прошли многократные проверки ShopBalance.
3. Переключить Bomb/Escort вне матча и повторить. Проверить наличие всех новых товаров, правильные цены и стороны, отсутствие отдельных скиновых товаров, сохранность пользовательских записей после перезапуска.
4. Проверить при доступных административных командах изменение цены/каталога и синхронизацию обоим клиентам. Не должно быть ArrayIndexOutOfBoundsException/ConcurrentModificationException в ShopCatalog, пустого или частично обновлённого магазина.
5. Если игра падает при загрузке с ошибкой Mixin/plugin — прислать новый полный latest.log. Ошибки авторизации, анимаций и рецептов из предыдущего лога не являются причиной обнаруженного серверного падения.
